# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**Calendar Auto Register** - LINEメッセージ・メールからカレンダーイベントを自動登録するシステム

### プロダクトコンセプト
- **メッセージ駆動の自動登録**: LINEメッセージやメールを送るだけで、テキスト・画像からイベント情報を自動抽出しGoogle Calendarに登録
- **LLMによる非構造化データ解析**: AWS Bedrock (Claude) を活用し、自然言語テキストや画像内のテキストからイベント情報を構造化抽出
- **Lambdalithパターンによるサーバーレス運用**: 単一のAWS Lambda関数上でFastAPIを動作させ、複数APIエンドポイントを低コストで提供

### プロダクトビジョン
日常生活で受け取るメッセージや画像に含まれるイベント情報を、手作業でカレンダーに転記する手間をゼロにする。
LINEにメッセージを転送するだけ、あるいは画像を送るだけで、AIが自動的にイベント情報を抽出・登録し、結果を即座に通知する。
カレンダーへの登録漏れを防ぎ、ユーザーが本来やりたいことに集中できる環境を実現する。

### 目的
- カレンダー登録の手間削減: メール・LINEメッセージからカレンダーへの手動登録作業を自動化し、登録漏れを防止
- 非構造化データの抽出検証: LLMを活用し、メール本文・LINEテキスト・画像などの非構造化データからイベント情報の自動抽出を検証
- Lambdalithパターンの検証: 単一のAWS Lambda関数上でFastAPIを動作させるアーキテクチャを検証

## ターゲットユーザー

### プライマリーペルソナ: 佐藤一郎（30代、個人ユーザー）
- LINE BOTと友だち登録済みの個人ユーザー
- 複数の予定（会議、イベント、支払い期限など）をGoogle Calendarで管理
- メールやLINEで届くイベント案内を手動でカレンダーに転記しており、登録漏れが発生しがち
- スクリーンショットやチラシ画像で届くイベント案内も多く、テキスト化の手間がある
- 1日の典型的なワークフロー:
  1. メール・LINEでイベント案内を受信
  2. 内容を確認し、日時・場所をGoogle Calendarに手入力
  3. 入力漏れで予定を忘れることがある

## 成功指標（KPI）

### プライマリーKPI
- カレンダー登録成功率: 90%以上（テキストメッセージからの抽出・登録）
- 重複登録防止率: 95%以上（±15分の時間窓による重複チェック）
- エンドツーエンド処理時間: テキストメッセージ 10秒以内、画像メッセージ 30秒以内

### セカンダリーKPI
- Webhook応答時間: 5秒以内（LINE Messaging APIタイムアウト回避）
- Lambda実行時間: 120秒以内
- エラー時のユーザー通知率: 100%（エラー時でも必ずLINEでフィードバック）
- 月間運用コスト: $20以下

## 機能要件

### コア機能（MVP）

#### F1: メールからカレンダー自動登録（既存機能）

**ユーザーストーリー**:
個人ユーザーとして、メールで届いたイベント案内を自動的にカレンダーに登録するために、メール解析・LLM抽出・カレンダー登録・LINE通知の一連のフローが欲しい

**受け入れ条件**:
- [ ] S3に保存された`.eml`ファイルからHTML/テキスト本文を抽出できる
- [ ] 送信元ドメインのホワイトリストチェックが動作する
- [ ] AWS Bedrock (Claude Haiku) でメール本文からイベント名・日時・場所・説明を抽出できる
- [ ] 支払い期限を自動検出し、別イベントとして追加できる
- [ ] 全角→半角の自動正規化が動作する
- [ ] Google Calendarに登録でき、±15分の時間窓で重複チェックが動作する
- [ ] 終日イベント/時刻指定イベントを自動判別できる
- [ ] イベント名に `⚙️` プレフィックスが自動付与される
- [ ] 登録結果（成功/重複/失敗件数と詳細）をLINE通知で受信できる

**優先度**: P0（必須）- 実装済み

#### F2: LINEテキストメッセージからカレンダー自動登録

**ユーザーストーリー**:
個人ユーザーとして、LINE BOTにテキストメッセージを送るだけでカレンダーに予定を登録するために、Webhook受信・テキスト解析・カレンダー登録・通知の機能が欲しい

**受け入れ条件**:
- [ ] LINE Messaging APIからWebhookを受信できる（`POST /line/webhook`）
- [ ] `X-Line-Signature` ヘッダーによるHMAC-SHA256署名検証が動作する
- [ ] テキストメッセージからイベント情報を抽出し、Google Calendarに登録できる
- [ ] 登録結果をLINEで通知できる（成功時: サマリ＋詳細、失敗時: エラー情報）
- [ ] Webhook受信後5秒以内に200 OKを返却できる
- [ ] 不正な署名のリクエストを403 Forbiddenで拒否できる

**優先度**: P0（必須）

#### F3: LINE画像メッセージからカレンダー自動登録

**ユーザーストーリー**:
個人ユーザーとして、スクリーンショットやチラシの画像をLINE BOTに送るだけでカレンダーに予定を登録するために、画像からのテキスト抽出・解析・カレンダー登録の機能が欲しい

**受け入れ条件**:
- [ ] LINE Content APIで画像バイナリをダウンロードできる
- [ ] Bedrock Vision (Claude 3) で画像からテキストを抽出できる（`POST /vision/extract-text`）
- [ ] 抽出したテキストからLLMでイベント情報を構造化抽出できる
- [ ] Google Calendarに登録し、結果をLINEで通知できる
- [ ] 画像処理を含めて30秒以内に完了する

**優先度**: P0（必須）

#### F4: 複数メッセージの順次処理

**ユーザーストーリー**:
個人ユーザーとして、短時間に複数のメッセージを送った場合でも全て処理されるために、メッセージの順次処理機能が欲しい

**受け入れ条件**:
- [ ] 各メッセージが個別に処理される
- [ ] 同時実行を避け、順次処理またはキューイングされる
- [ ] 各メッセージごとに結果が通知される

**優先度**: P1（重要）

## 非機能要件

### パフォーマンス
- Webhook応答時間: 5秒以内（LINE Messaging APIタイムアウト回避）
- テキストメッセージ処理: 10秒以内（Webhook受信からLINE通知まで）
- 画像メッセージ処理: 30秒以内（Webhook受信からLINE通知まで）
- Lambda最大実行時間: 120秒
- LLM抽出リトライ: 最大5回（エクスポネンシャルバックオフ）

### セキュリティ
- Webhook署名検証必須（LINE Channel Secretを使用したHMAC-SHA256）
- 画像の一時保存はプライベートS3バケット（パブリックアクセス完全ブロック）
- S3オブジェクトは24時間後に自動削除（ライフサイクルポリシー）
- API Key認証（既存ミドルウェア継続使用）
- SSM Parameter Store（SecureString）による機密情報管理

### 信頼性
- エラー時でもユーザーへのフィードバック必須（LINE通知）
- リトライ可能なエラーは自動リトライ（LLM: 5回、Calendar/LINE: 3回、Vision: 2回）
- CloudWatch Logsによるエラートラッキング
- リクエストID付きトレーシング

### ユーザビリティ
- LINE BOTに友だち登録するだけで利用開始可能
- テキスト・画像を送信するだけの直感的な操作
- 登録結果はサマリ（成功/重複/失敗件数）＋詳細（日時・場所・エラー情報）で通知

### スケーラビリティ
- 月間想定処理量: 1,000リクエスト/月
- Lambda同時実行数: デフォルト（必要に応じてリザーブド同時実行設定）
- 月間コスト: $10-20以内

## スコープ外

明示的にスコープ外とする項目:
- マルチユーザー対応（現時点では単一ユーザー向け）
- Web UI / モバイルアプリ
- イベントのリマインダー機能
- 動画メッセージからのイベント抽出
- リアルタイムチャットボット機能（対話的なやり取り）
- Google Calendar以外のカレンダーサービス連携
